问题原因

问题在于不熟悉RFC的合规性要求，Requests库收到一个响应时，Requests 会猜测响应的编码方式，用于在你调用 Response.text 方法时对响应进行解码。Requests 首先在 HTTP 头部检测是否存在指定的编码方式，如果不存在，则会使用 charade 来尝试猜测编码方式。

只有当 HTTP 头部不存在明确指定的字符集，并且 Content-Type 头部字段包含 text 值之时， Requests 才不去猜测编码方式。在这种情况下， RFC 2616 指定默认字符集必须是 ISO-8859-1 。Requests 遵从这一规范。如果你需要一种不同的编码方式，你可以手动设置 Response.encoding 属性，或使用原始的Response.content。

我的案例正好符合这种情况，因为请求的是文件下载，返回的header中并没有指定编码方式，因此服务器默认以 ISO-8859-1 编码返回了数据，Python 在处理的时候，也必须将 ISO-8859-1 转换为环境中的 UTF8 格式才能在命令行中正确显示，这还是吃了不熟悉规范的亏呀。
